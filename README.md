# binit

Move files to the Windows Recycle Bin from the terminal. Windows ships no
command that does this: `Remove-Item` and `del` destroy permanently, and
`Clear-RecycleBin` only empties the bin.

**binit cannot delete a file permanently.** `IFileOperation` does not actually
guarantee recycling — on a volume with the Recycle Bin disabled, on a network
share, or for a file over the bin quota, it silently deletes permanently
instead. Nearly every trash tool on Windows carries that bug. binit vetoes the
operation in `IFileOperationProgressSink::PreDeleteItem` unless the shell has
committed to recycling, so an item is either in the Recycle Bin or still on
disk. There is no `--force`, and there never will be.

## Install

```powershell
cargo build --release
# then put target\release\binit.exe on PATH
```

Windows 8 or newer. Single executable, no runtime. Builds with Rust 1.95+
and needs `rustfmt` on the PATH at build time (the Win32 bindings are
generated by `build.rs`).

## Usage

```
binit <path|glob>...

  -v, --verbose    Print each item trashed
  -n, --dry-run    Show what would be trashed; change nothing
  -q, --quiet      Suppress the summary line
      --json       Machine-readable output on stdout
      --no-color   Disable color
  -h, --help       Show this help
  -V, --version    Show version
```

```powershell
binit unicorn.png rainbow.png
binit *.log
binit --dry-run build\
binit --json old-data.csv
```

`-r -f -i -d -P -R -W` are accepted and ignored, so `binit -rf build\` works
from muscle memory.

binit never prompts. Recycling *is* the confirmation step.

Exit codes: `0` everything recycled · `1` one or more items failed · `2`
invalid usage · `3` the shell could not be initialized and nothing was
attempted.

A refusal never affects the other arguments: items queued behind a refused
one are re-run in a fresh batch, so each path gets its own verdict.

When binit refuses:

```
binit: refused: \\srv\share\b.txt
  Network locations have no Recycle Bin, so the file could only be
  deleted permanently. binit never does that. Nothing was deleted.
  To delete it anyway: Remove-Item '\\srv\share\b.txt'
```
